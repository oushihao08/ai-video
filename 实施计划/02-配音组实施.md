## 实施步骤

1. 核对当前导入和外部命令，只迁入必要底层。使用新配置位置；不读取旧 Skill 的 `.env`、内容规则或日志作为生产依赖。环境缺项报告变量名称，不输出密钥值。
2. 实现生成入口：先通过00提取正文/标注、核对审核或冻结依据，再准备合成。过期、缺失或需修订的依据在发起请求前失败；不提供默认跳审通道。
3. 保持当前火山声线与基础原速；逐项核对现有 API/版本对表达控制的支持。标注意图转换为实际请求，无法支持的项明确反馈；不偷偷换引擎或声线。去掉新生产入口对 `say` 的隐式选择。
4. 首版以可稳定映射的句段为合成单位。检查旧逐句策略的衔接，再决定是否需要局部段级合成；不能只因希望自然就丢失句子映射。段级方案若无法可靠对齐，先记录缺口或保留可用策略。
5. 定义片段缓存身份：实际发送文本、声线、语速/表达参数、发音处理及参与合成的上下文；同时校验产物音频指纹。不因某一句变化重生成所有未变片段；如上下文参与合成，明确实际受影响范围。
6. 写 timing：源文件时长、句段源区间、可用的词时间与精度、稿件/声音输入摘要。确认响应时间单位，不把毫秒当秒；校对范围不超出实际音频。缺词时间则如实保留句段级精度，不平均分配冒充实测。
7. 补已有音频接入：可用文本/对齐直接引用；缺失时只调用当前已有且获准的转写/对齐能力，不为首版新增一整套 ASR 系统。无法可靠对齐则交付支持的粒度，通知03调整同步要求。
8. 生成短稿，实际听查发音、停顿、强调和句间衔接；记录时间码与修正。失败只保留有效片段，不把半成品记录为完整 timing；再次运行复用已完成且输入未变的片段。

## 输入输出的关键界限

- `script.md` 为显示与审核正文；发音替换不静默改显示文本，保留用于合成的对应关系并计入声音摘要。改变实际语义必须退回01。
- timing 中零点属于源音频，不属于成片。03新增两秒留白不应导致02重生成源音频。
- `review.json` 不等于缓存授权：每次正式生成/复用前先核对当前依据；即使缓存命中，失效审核也不能自动放行新任务。
- 分钟/秒阅读格式由03视听脚本展示；02提供真实数值与粒度，不虚构成片起止时间。

## 验收与交接

| 场景 | 所需证据 |
|---|---|
| 有效短稿生成 | 真实 API 调用、可用音频、ffprobe 实测时长与输入绑定；不是旧缓存冒充新调用 |
| 改稿后沿用旧审核 | 请求发出前拒绝；记录具体不匹配项 |
| 输入不变再运行 | 复用同一有效片段；输入与音频指纹相符 |
| 只改表达或发音 | 对应片段生成新声音/时间，未变片段复用；内容语义不变时正文审核仍有效 |
| 中途失败后恢复 | 已完成片段可复用，失败片段可定位，不输出误导性的完成状态 |
| 时间映射 | 句段区间与实际音频对应；精度不足有说明，词时间不超出源范围 |
| 实际表现 | 有真实听查记录与问题位置；修正后复听相关衔接，未听查不得报告自然度通过 |
| 外部音频 | 原文件保持，文本/对齐来源与精度清楚；缺对齐能指出阻碍 |

向03交付源音频、timing、当前正文引用、实际声音参数和听查缺口；向04交付入口命令、错误与恢复行为。无需安装 Remotion，也不输出最终镜头时长或字幕成片偏移。

没有凭据或调用授权：继续完成读取、缓存身份、依据检查和时间结构，真实调用标未完成。没有听查能力：音频生成结果可交付，但表现验收不通过。格式示例不能补造 user-frozen 或实际审核记录以绕过阻碍。

## 实施交接记录

已创建 `story-studio/skills/story-voice/SKILL.md`、`runtime/voice/generate.mjs`、`runtime/voice/import-audio.mjs`、`runtime/voice/audio.mjs`、`runtime/voice/cache.mjs`。

- 正式入口：`node story-studio/runtime/voice/generate.mjs --episode <本期目录>`；默认读取本期 `script.md`、`review.json`，写入本期 `audio/`。路径可用 `--script`、`--review`、`--out` 改为本期内相对路径。发音映射用 `--pronunciations`；未能从约定推导的额外审核文件路径用 `--basis-path 字段=相对文件`。
- 已有音频入口：`node story-studio/runtime/voice/import-audio.mjs --episode <本期目录> --audio <音频文件>`；可加 `--script`、`--alignment`。原文件保留，本期按音频摘要产生副本，重新导入不覆盖旧副本；上次时间记录另存 `timing.previous.json`。有对齐时要求句 ID 按正文顺序、正时长且不越过源音频；无真实对齐时只输出 `audio-only` 精度。
- 正式入口逐项重算 `review.basis`：`scriptSha256` 使用共享正文摘要，`rulesSha256` 使用当前 story-review 原始文件，共同内容原则用 `contentPrinciples:{path,sha256}`（路径相对 story-studio 根），其他 `{path,sha256}` 及来源列表从本期实际文件重新读取。缺失或失效依据、`user_frozen` 未经可信对话核实时，在请求前失败。当前 CLI 不提供用户冻结放行开关。
- 每句一个按输入摘要命名的源 WAV，修稿或失败恢复不会覆盖旧时间记录引用的音频；`timing.json` 的 `audio[].audioId` 对应句 ID，`sourceFile` 相对本期，`sentences[].startSeconds/endSeconds` 相对该 WAV 的零点。词时间只在数值有序且不越过 ffprobe 实测源时长时输出，其他情况降为句级。生成结果写 `source: volc-tts`；缓存命中写 `source: verified-cache`，并校验片段输入摘要与音频文件摘要。新一次生成开始时旧完整记录移到 `timing.previous.json`，失败时不写新完整 timing，已成功片段的缓存留待恢复。
- 静态核对了旧 `tts.mjs`、`content-cache.mjs`、`tts-s20.mjs` 与 `make-sentences.py` 的耦合；新入口不读取旧 `.env`、旧审核、工作流日志或 `say` 引擎。2026-10-12 从用户指定的本机配置读取 TTS 凭据，仅传给配音进程。独立审核依据先通过摘要核对后，真实生成11句 WAV 与词级时间；稿件和声音指纹匹配，测量总长约78.1秒。目标音频流峰值为 -8.6dBFS，无削波迹象。隔离副本恢复演练：只调整 s002 表达后，真实 API 仅生成该句、缓存复用其余10句；正文变化则在 TTS 请求前被旧审核摘要拦截。另用成功的模拟 TTS 响应后注入第二句 HTTP 503，确认第一句新缓存保留、旧完整记录移到 `timing.previous.json`、失败句无新完成音频、当前 `timing.json` 不会误报完整；此项验证了运行层恢复逻辑，不代表实际供应商中断。真人听查仍未验收。密钥没有写入项目或运行日志。
