# 01：内容组实施

状态：三个独立 Skill 已建立；真实材料策划、正文、视听提前对接与独立审核通过。声音和画面用户验收由02、03、04记录。前置：00的 handoff、公共读取能力与格式示例已交付。可与02、03A分别实施；完整视频的正式稿需与03A提前对接。

## 目标与共同实施的理由

一起实现 story-plan、story-write、story-review，保持三个独立入口。它们共同处理来源、主脉络、段落职责、正文落实和审核依据；用同一真实材料串通后再分别交付，减少“骨架要求一套、写作一套、审核又一套”。

先读[实施入口](README.md)、[00](00-最小交接基础.md)、总计划第3—5节及已实施 handoff。旧规则按需读：

- [story-planner](../../ai-videoxxx/skills/story-planner/SKILL.md)。
- [材料与选题规则](../../ai-videoxxx/skills/investigation-video/references/editorial-and-materials.md)。
- [内容生成规则](../../ai-videoxxx/skills/investigation-video/references/content-generation.md)。

仅提取新目标需要的内容原则，不照搬旧叙事结构注册、审核轮次、日志或总控。

## 文件责任与输入输出

新建 `story-studio/skills/story-plan/`、`story-write/`、`story-review/` 下的 SKILL.md 和确有需要的简短 references。正文解析与摘要导入00能力，本包不另实现。实际演示产物放 `<episode>/`；不用本包生成稿充当用户优秀范文。

| 入口 | 最小输入 | 交付 | 停止位置 |
|---|---|---|---|
| story-plan | 主题或材料、当前目标和事实/虚构范围 | 来源索引、主要依据、主脉络与段落骨架；需要分集时一份系列说明 | 只要研究/骨架就交付，不生成正文或音频 |
| story-write | 骨架/待改稿、相关来源、表达要求 | 正文、句段 ID、必要声音标注、作者自审 | 写稿结束；完整视频接收03A反馈后修订关键段落 |
| story-review | 实际待审对象、当前要求、相关来源；有则附骨架/视听设计 | 具体缺陷及依据、通过/需修订、输入摘要 | 不默认重写，不因骨架通过而核准正文 |

外部稿件不强制补造研究过程；没有实际依据则注明限制。历史事实不得因为需要表演补造人物心理或对白；虚构任务按用户授权范围创作。

## 实施步骤

1. 写三个入口的触发、最小输入、阶段结束、返回条件；只通过 handoff 共享交接规则，内容原则在本组三者引用的适用位置定义一次。
2. 落实策划：明确观众所得，选择材料支持的主线，保留关键行动的关系、理由、限制和结果；缺资料定向回查。只有改变核心范围/分期等重大决定才询问。
3. 落实播讲稿：语言按听者理解顺序组织，实际解释关键关系；必要表达标注具体到作用范围，不给每句平均加情绪。单独写稿不强制生成分镜。
4. 落实审核：作者自审先改已发现问题；独立上下文直接读正文与来源，定位问题到句段。正文与画面有意分担信息时核查设计是否完整，不能假想画面已实现；音频单独交付则正文自身要能讲清。
5. 绑定00约定的实际输入摘要。审核方式、作者自审和用户冻结分别记录；不能由格式校验器判断“文章好”。只有标注变化且未改语义时沿用正文依据；主张改变重新审。
6. 用一份实际提供或核实过的短材料走完研究→骨架→正文→审核；另取一处故意遗漏必要解释的副本，核对是否被定位。缺陷副本标演示，不覆盖正式稿。
7. 与03A做提前对接：视频方给出关键画面状态变化和声音/画面分工，内容方检查必要信息、表达与来源；需要改文时先改并审核，再交02配音。

## 提前对接必须共同完成什么

共用同一份正文和句段 ID；逐个检查关键叙事单元“新信息是什么、谁表达、哪里需要停顿或看图、画面是否暗示额外事实”。不固定镜头数，不逐句绑定一个镜头。03写 shots，01写正文；双方不同时改对方真源文件。

对接产物为当前正文、初始 shots、可读视听脚本和对应审核依据。此时最终音频时间可以缺失并标估算。若03尚未完成，01可以交付独立内容能力，但不能报告完整视频视听协作已验收。

## 验收与交接

| 验收场景 | 通过依据 |
|---|---|
| 只要骨架 | 有连贯主脉络、分段职责和出处；没有越界生成正文/音频 |
| 改现成稿 | 保留用户有效约束和未涉及内容；新事实有依据，正文可被00读取 |
| 骨架完整但正文缺关键原因 | 审核引用缺口相邻句段及材料，判需修订；不替正文脑补 |
| 正常稿独立审核 | 有实际独立阅读和文本依据，审核记录绑定当前文件；不能只复制作者结论 |
| 完整视频协作 | 同一视听阅读视图能看出内容与画面的任务，实质修改后的审核有效 |
| 修改正文 | 旧审核被共享依据检查判过期；重新审核后的实际新版本可交接 |

向02交付：正文、表达标注、审核/真实冻结依据与来源关联。向03交付：骨架、正文、语义约束与当前版本。向04交付：三个入口的实际调用方式、停止/返回条件、演示记录。

本包不验收声音表现或动画效果。独立审核能力暂不可用时可先完成作者稿和规则，明确审核未完成，不能自签独立通过。正式题材缺失不影响 Skill 规则编写，演示材料须标身份。
