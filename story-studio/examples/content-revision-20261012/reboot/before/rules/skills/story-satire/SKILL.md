# 嘲讽评论

让具体材料承载批评与嘲讽。从选材和构思参与，按本期要求形成荒诞、不满、解气或其他效果；态度不预设为持续愤怒。

## 入口与边界

先读当前要求、材料和有效本期记录，再读 [共同内容原则](../story-plan/references/content-principles.md) 与 [交接](../../references/handoff.md)。对象、受众、情绪、体量和改写范围从本期确定；缺项按共同规则处理，例子不提供默认条件。

直接调用时，按实际请求进入策划、写作或审稿，复用相应阶段职责与文件；只要稿件就在交稿处停止。已在阶段内时读取本方法后继续该阶段，入口之间不递归调用。与历史等方法组合时，在骨架简记主组织方式及辅助方法作用处，产出同一份正文。

事实、来源归属与授权虚构保持各自身份。评论可以明确尖锐，不要求机械平衡；独立审核交 `story-review`，本专项不自签通过，不承担配音、渲染或另一套来源流程。

## 构思：找到可以落笔的关系

1. 对准用户要评论的对象，指出材料里具体哪项行为、说法或结果值得评论。例如承诺与兑现、同一标准的不同用法、命名与实际内容之间的关系；这是寻找落点的方向，不是必须出现的冲突清单。
2. 回查关系两端的依据，以及会改变判断的背景或反证。材料只支持一场或一人，就让评论落在该范围；未记载的心理、动机、言论与群体反应不作为连接。预设批评不成立时明确修正说法，保留原对象，不靠换题维持嘲讽。
3. 选择最能让听者看见这层关系的细节与组织。材料没有反转时，使用它实际支持的评论角度；若无法支撑请求中的关键指控，标明缺口。骨架写清评论怎样由材料成立，避免先排成材料通报，再贴情绪词。

## 写作：让听者接到评论

- 根据落点选择直说、冷述、对照、反问、复述后呈现结果或连续叙述。判断每种办法是否使关系更清楚、态度更可感，选有用部分，不把办法串成固定段落步骤。开场、结尾、反转次数由当前内容决定。
- 用具体处境、代价、细节与反差形成力度；平实交代可以为评论蓄力，嘲讽不必句句出梗。删去无实际所指的狠话、口号或吊胃口语句后，检查剩下的材料和判断能否完成当前表达。
- 区分原话、作者判断和修辞。反语或夸张可能被误认作事实时，让上下文、具体表达标注或必要标识说明其身份；需要新增事实才能成立的笑点，回到材料重新选择。关键限定就近说清，不把核验日志朗读成主线。
- 声音承载关键反语时，在相应句 ID 标注具体重音、停顿或态度的作用；不要用“冷笑”等标签替代表达设计。尚无具体画面设计时，独立听正文也应能读懂评论。

方法例子（只示意差别）：材料明确记载某服务承诺“零等待”，实际等待十分钟。可以直接评论承诺落空，也可以冷述“零等待”的名目后呈现十分钟。两种选择都依赖同一关系；不能补造经营者故意欺骗的心理。这不是默认题材、语气或开场。

## 自审与交付

读实际正文：听者能否知道在评论谁、哪项行为、为什么如此评论；尖锐处是否有材料承托；反语是否可懂；有没有把对对象的评论换成劝观众保持理性。按具体问题修稿，不以个人温和偏好消除已获要求的态度。

沿用 `script.md` 的句段 ID 和可选表达标注；在 `outline.md` 简记实际采用的方法与材料连接，相关要求与自主选择分开记录。来源、未解决项及审核交接复用现有约定，不产生第二份可编辑正文或专项审核轮。
