# 本期交接约定

本文件只定义内容、配音、视频同时使用的字段与边界。每期文件相对于 `<episode>/` 定位；`story-studio` 的共享模块从集合自身路径定位，调用时 cwd 不改变含义。当前生产入口尚未全部实现；以下是交接契约，不是已运行证明。

## 文件与负责方

| 文件 | 唯一编辑方 | 必要内容 |
|---|---|---|
| `episode.md` | story-produce；独立调用时由当前 Skill 记录 | 当前目标、事实或虚构、停止阶段、有效文件与阻碍。已有稿单独工作时允许无骨架 |
| `research/` 与 `outline.md` | story-plan | 来源、主脉络、段落职责、必要解释；明确估时或用户硬时限 |
| `script.md` | story-write；外部原稿接入时保留原文副本 | 唯一口播正文、句段 ID、必要表达标注 |
| `review.json` | story-review | 当前稿件审核或用户明确冻结决定的真实记录；不能由程序生成“内容通过”结论 |
| `audio/timing.json` 与音频 | story-voice | 源音频、实际时长与可靠的句段/逐字源时间；不含成片偏移 |
| `visual/shots.json`、`direction.md`、`scenes/` | story-video | 叙事单元、分镜与最终剪辑时间；只引用正文和源音频时间 |
| `output/` | story-video；交付记录由 story-produce 整理 | 阅读视图、预演与最终产物。阅读视图是派生文件，不是第二份编辑真源 |

## 稿件格式

一个段落标题写 `## [seg-01] 标题`；口播句一行写 `[s001] 这一句的正文。`。可选表达标注写 `> 表达 [s001]：具体、可执行的语气或停顿作用`，不进入 TTS 朗读文本。段落/句子 ID 在同稿唯一；改措辞时保留 ID，拆合句时重分配 ID 并更新下游引用。

`script.md` 允许一个 `#` 文档标题、空行和以上三种内容行；未知非空行必须报告，不能静默丢掉可能要读的正文。引用与来源文字写 `research/` 或 `outline.md`，避免被误读。当前共享解析器导出 `parseScriptMarkdown()`，返回有序的 `{segments, sentences, deliveries}`；`contentDigest()` 覆盖有序段落 ID、句子 ID 与实际正文，`deliveryDigest()` 只覆盖有序表达标注及作用对象。函数签名见 `runtime/shared/content-contract.mjs`。

完整视频先由 story-write 与 story-video 按同一段落/句子 ID 对齐必要信息，正文审核后再正式配音；单独写稿或无声动画可停在对应阶段。视频中的镜头可跨句，单元可含多句，不强制逐句切镜。

## 审核依据与失效

独立审核记录使用 `type: "independent_review"`、`status: "passed" | "needs-revision"`、`basis`、`unresolved` 和问题位置。`basis` 至少含 `scriptSha256`、`rulesSha256`；实际使用骨架、要求、来源与影响内容理解的视觉设计时，分别记录其摘要。来源按相对路径与摘要列出，顺序固定。视觉依据默认对文件原始字节求摘要；`visual/shots.json` 使用 `digest: "visual-content-v1"`，只跟踪单元信息、开始/变化/结束状态、同步意图、来源和场景输入，不跟踪画布尺寸、镜头帧数/位置或音频放置。纯构图/留白调整应使视频预演过期，但不使正文审核或源配音过期。程序只检查记录与当前输入是否一致，不判断故事好坏。

外部稿由用户**明确决定冻结**时记录 `type: "user_frozen"`、稿件摘要与实际决定来源。这个分支不是 AI 审核通过；当前任务的操作者必须从可信对话核对该决定，不能因为仓库里出现 `user_frozen` 字符串就自行获得授权。示例目录不含有效审核或冻结凭据。

`validateReviewAuthority(review, currentBasis)` 只接受当前摘要逐项匹配、无未解决问题的独立通过记录；用户冻结分支必须由调用方另外明确传入已核实的可信决定。缺项、旧摘要、状态不通过时在请求 TTS 前失败。已缓存音频也不能让旧审核放行新稿。

正文摘要与表达摘要分开。只改有效表达标注且未改正文语义时保留正文审核，重新计算声音缓存和时间；改正文则旧审核失效。`visual/shots.json` 的镜头时长、位置、构图不进入正文审核摘要；声画分工、视觉事实与必要信息若改变，内容审核需要复核相关判断。不能单纯对整个 shots 文件做一个审核摘要。

## 时间与路径

源音频区间统一用秒，零点属于各源文件；`audio/timing.json` 明确音频文件与指纹、稿件与声音输入摘要、实测总长、时间来源与精度。句段时间只有实际确认的粒度；缺逐字信息不以均匀分配填充。

配音前 `visual/shots.json` 的时间可为估算并显式标注。最终视频的镜头边界、字幕、音频放置共用一条剪辑时间轴：源入/出点用秒，成片起点与长度按帧率换算为帧；秒转帧统一 `round(seconds × fps)`，相邻镜头共享边界。额外留白占用成片时间，不修改源时间；源音频内已有停顿不得再次添加。无声镜头可以没有音频引用。时间来源或精度不足以支持关键同步时，补对齐或调整画面设计。

最终 `shots.json` 每镜至少有 ID、关联单元/句段、意图、开始/变化/结束状态、场景入口、资源、开始帧和帧数；声音放置另记录源音频 ID、源入/出点、成片起点。阅读视图组合 `script.md`、`timing.json`、`shots.json`，显示“分:秒—说什么—怎么说—画面发生什么”和时间状态。它不得反向修改正文、源时间或镜头。

## 变更次序

共享字段变化先修本文件和格式示例，再通知01/02/03调整各自读写；不建第二套名称。只涉及某包内部的字段留在包内。每个实施包在自己的计划末尾留下实际产物、命令与证据，不用计划中拟建命令代替真实运行结果。
