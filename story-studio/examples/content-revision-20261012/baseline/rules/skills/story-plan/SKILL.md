# 故事策划

从本期目标与材料选出有依据的主线。研究、骨架和系列规划可以分别交付；用户只要骨架时停在骨架。

## 输入与停止点

读取当前任务、用户材料、受众与时长要求，区分事实任务与获授权的虚构任务。缺少的普通表达选择自行判断；若不同选择会改变主题主体、核心覆盖或期数，给出具体推荐及影响后问最小必要问题。独立调用时在 `<episode>/episode.md` 记录本期目标、事实范围与停止阶段；若已有记录，保留有效约束。

## 研究与组织

1. 先检查已给材料与当前任务相关的原文；只为会影响主线或关键解释的缺口定向补查。事实任务在 `<episode>/research/` 保存简短索引：稳定来源 ID、出处及可定位位置、支持的说法、适用边界、未解冲突。重要事实要能回到原文；用户限定仅用所给材料时标明未外查。虚构内容与真实依据分清。
2. 用材料判断观众最终应明白什么、主要变化或机制是什么。写一段具体 `mainNarrative`，交代主体、处境、发展、必要连接、结果及有影响的未知。不要把研究问题自动写成口播问句，也不要套固定幕数。
3. 在 `<episode>/outline.md` 按主线列段落 ID、每段给观众的新信息/行动、段落职责、必要解释、来源 ID 与下一段为何接续。事件中的关键选择须检查关系、理由、限制、代价与结果；只有影响本期理解的内容才进入必要解释。背景和趣闻按作用取舍。
4. 先判断材料所需体量，再写预计旁白时间及估算依据。用户明确时限标为硬约束；没有时限不编造固定分钟数。内容少而完整就保持短；关键事实不足则限定说法、调整范围或保留阻碍。
5. 需要系列时，另写一份系列说明：整体承诺、每期独立交代的结果、分集边界、已讲/待讲背景。分期若实质改变用户目标，先解决该决定。

## 交接与核对

遵守 [本期交接约定](../../references/handoff.md)。`outline.md` 的 ID 供 story-write 和 story-video 引用；来源索引只导航，写稿与审核仍要读相关原文。复核每段是否推进同一主线，重要过渡是否有依据，哪些推断或未知仍在。交付时说明实际来源、估时身份与尚未解决的内容；未要求正文就不要生成 `script.md`、音频或分镜。

内容取舍的共同判断见 [内容原则](references/content-principles.md)。
