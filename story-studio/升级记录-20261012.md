# 内容与视频套件升级记录

本次落实用户对整套内容生成到视频程序的修改要求。保留六个阶段入口、嘲讽与历史两个专项、一套Remotion运行层，不增加互相竞争的正文格式或风格枚举。八个本机Skill入口仍通过软链读取本项目文件。

## 已实施

| 范围 | 实际修改 | 解决的问题 |
|---|---|---|
| 共同构思、story-plan | 用讲述关系、观众关注、信息顺序与兑现组织本期；结构条件选择 | 不再把动作开场或五项关系写成统一顺序；观察、说明、结果先行可按材料使用 |
| story-write | 从实际说话目的和听者理解顺序成稿，连续单元允许多句，必要解释保留 | 去掉策划说明扩写、重复总结；不以口头禅或强行电影感代替讲述 |
| story-satire | 选择有材料支持的反差、顺推、回扣等机制；核对实际因果与靶子 | 强烈措辞、最后一句俏皮话不自动等于嘲讽成立 |
| story-history | 按人物、事件、生活观察、制度的材料尺度组织 | 不为所有历史题材强造冲突、心理、成长或假悬念 |
| story-review / produce | 先接触作品再看作者说明；文字制作资格与真实效果分开记录 | 作者解释、格式通过、旧审核不能替代作品效果 |
| story-video | 现有direction记录视角、声画分工、揭示和反应时间 | 分镜参与讲述，不只是角色配色表和旁白配图 |
| 配音生成 | `--ids`预演、总体与局部读法合并、词时间归一化边界修复 | 可以先做关键片段并复用；局部标注不会抹掉整体身份；零长词不会在渲染时才暴露 |
| 字幕 | 独立subtitleCues、真实词时间分句、降级说明 | 连续配音不再导致整段文字提前显示；不制造均匀词时间 |
| 渲染与恢复 | rendererSha256、表达摘要检查、字幕限制出现在恢复状态 | 新程序不会把旧成片当成已生效；旧表达音频不能静默用于新读法 |
| 本机配置 | 仅TTS必要字段独立保存到Git忽略的私有配置，权限600 | 运行不再依赖旧项目配置；密钥不进入记录或日志 |

创作方法依据在[电影故事方法](skills/story-plan/references/storytelling-foundation.md)。火山语音指令能力依据[官方HTTP文档](https://docs.volcengine.com/docs/DoubaoVoice/unidirectional-streaming-text-to-speech-http?lang=zh)：context_texts要求支持该能力的2.0音色；默认资源已与本项目实际使用的2.0声音配对，显式环境配置仍可覆盖。发出指令不保证表演达到要求。

## 新材料创作与纠偏

隔离创作任务读取新规则，未读取影院、食店旧稿，产生两份作者自选虚构生活材料。具体题材不是用户指定，不作为新闻事实。

- [自助奶茶店](examples/suite-upgrade-20261012/fictional-service/script.md)：轻调侃，继续制作完整媒体。初稿把顾客失手造成的清理当成店内额外服务，主线程和独立审核均指出因果与嘲讽对象不相接；保留[first-draft](examples/suite-upgrade-20261012/fictional-service/first-draft.md)，改为系统在饮品完成后追加倒茶渣、冲洗要求。现行[独立审核](examples/suite-upgrade-20261012/fictional-service/review.json)绑定修改后的正文和声画设计。
- [两颗桃子](examples/suite-upgrade-20261012/plain-observation/script.md)：平静观察，没有强制嘲讽、反转或成长；[独立审核](examples/suite-upgrade-20261012/plain-observation/review.json)确认动作关系可辨，也明确内容分量轻。本篇只验证文字方法的差异，不作媒体效果证据。

这不是同材料匿名优劣实验，也不证明全题材稳定成功。新样例说明方法可以迁移，并暴露了需要实际修稿的问题。原失败样片和上一轮reboot正文没有被覆盖，旧审核依现行规则显示过期。

## 实际程序检查

1. 独立正文和声画设计审核通过后，真实火山请求预演s003，生成1个片段；完整生成另生成2个，复用预演1个。三个单元共25.752秒真实声音，带词级时间。
2. 完整声音存在后再次预演s003，复用缓存且`timing.json`前后SHA-256一致；[预演记录](examples/suite-upgrade-20261012/fictional-service/output/preview-check.json)保留结果。局部记录状态始终为preview，未伪装完整声音。
3. 真实新音频暴露30毫秒词首尾四舍五入到同一视频帧的问题，初版字幕因此整段回退。已改为先按真实边界合并短语，再判断显示区间；没有制造新词时间。当前3个口播单元生成18条短字幕，无降级，末句回应在802–828帧才显示。
4. 使用当前程序和真实音频生成890帧、29.667秒自定义动画；画面中机器提示、水池动作与最后日历按实测词时间触发。[视频](examples/suite-upgrade-20261012/fictional-service/output/story-studio.mp4)、[视听脚本](examples/suite-upgrade-20261012/fictional-service/output/视听脚本.md)。最终媒体检查以本期output与episode记录为准。
5. 最终MP4为1280×720、30fps、H.264/AAC，封装时长29.717秒，全片FFmpeg解码成功。六个实际关键帧确认人物与字幕无相互遮挡、包袱与日历按设计先后出现；QuickTime实际播放进度到片尾并停止。恢复状态为当前输入与渲染相符、无字幕降级。完整[验证记录](examples/suite-upgrade-20261012/fictional-service/output/verification.json)和[关键帧](examples/suite-upgrade-20261012/fictional-service/output/contact-sheet.png)可回查。播放器进度由工具观察，明确记录为observed_player_playback，不冒充人工听查。

执行了必要的解析、语法核对、真实配音、缓存复用、准备与渲染检查；未新增测试文件，未运行测试框架、lint、开发服务，未安装依赖或修改package.json。

## 使用

从项目根运行，已有稿件必须取得真实有效的当前审核。不同目录运行时改成绝对路径：

```sh
# 关键配音预演；总体语气可通过VOLC_TTS_STYLE传入
node --env-file=story-studio/.env.local story-studio/runtime/voice/generate.mjs --episode <本期目录> --ids s001,s003
# 完整声音，自动复用相同输入的有效缓存
node --env-file=story-studio/.env.local story-studio/runtime/voice/generate.mjs --episode <本期目录>
# 按真实声音完成shots的时间，然后准备、检查限制与渲染
node story-studio/runtime/remotion/cli.mjs prepare <本期目录>
node story-studio/runtime/remotion/cli.mjs render <本期目录> --browser-executable='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome'
node story-studio/runtime/produce/status.mjs <本期目录>
```

## 效果边界

短语字幕仍以短语整体显示；若落点依赖某个短语内部最后一字，须检查字幕与画面的实际揭示。对齐文字与正文不匹配时明确回退，不冒充词级可靠。现阶段不把文件、实际合成、解码、帧检查或播放器进度冒充听感。没有能力听辨真实声音时，记录未确认，仍交付可播放作品，不让用户反复授权已允许的制作步骤。用户若指出平淡、难懂或不好笑，返回对应创作环节，不能以本记录的技术检查为其开脱。
