# 本期交接约定

本文件定义内容、配音、视频同时使用的字段与边界。每期文件相对于 `<episode>/` 定位；`story-studio` 的共享模块从集合自身路径定位，调用时 cwd 不改变含义。命令与规则的存在不证明本期内容、声音或画面已验收。

## 文件与负责方

| 文件 | 唯一编辑方 | 必要内容 |
|---|---|---|
| `requirements.md` | story-produce；独立调用时由当前内容 Skill 保存 | 有影响的用户原话、有效更改及真实来源；作者自主选择另记，不能冒充用户决定 |
| `episode.md` | story-produce；独立调用时由当前 Skill 记录 | 入口、事实或虚构身份、停止阶段、有效文件、状态与阻碍；指向内容要求。已有稿可无骨架 |
| `research/` 与 `outline.md` | story-plan；写作重排时同步骨架 | 来源、实际构思 mainNarrative、讲述关系与观众关注、信息顺序与落点、实际方法分工；明确估时或硬时限 |
| `script.md` | story-write；外部原稿接入时保留原文副本 | 唯一口播正文、句段 ID、必要表达标注 |
| `review.json` | story-review | 当前稿件审核或用户明确冻结决定的真实记录；不能由程序生成“内容通过”结论 |
| `audio/timing.json` 与音频 | story-voice | 源音频、实际时长与可靠的句段/逐字源时间；不含成片偏移 |
| `visual/shots.json`、`visual/direction.md`、`visual/scenes/` | story-video | 本期导演意图、声画分工、叙事单元、分镜与最终剪辑时间；只引用正文和源音频时间 |
| `output/` | story-video；交付记录由 story-produce 整理 | 阅读视图、预演与最终产物。阅读视图是派生文件，不是第二份编辑真源 |

## 要求与方法

按 [内容判断与方法选择](../skills/story-plan/references/content-principles.md) 决定适用方法。专项直接调用或被阶段 Skill 读取，均复用以上产物，不建立第二份正文、全链或审核。方法选择、组合和实际调整简记在骨架或本期已有记录，不新增风格枚举和审批。

`requirements.md` 保存会影响创作的原话与更改及可信来源，不复制无关聊天；另区分材料事实、验收任务定义和作者选择。自主选题、时长、语体、解释范围不得写成用户指令；作者选择若缩小用户目标须回到原目标核对。审核者须获得可信当前任务，不能只信作者重述。纯对话可直接使用可信要求；进入持久化新稿审核与正式配音前保存必要要求。原始要求改变时更新真实内容；只写制作进度更新 episode，不随之重写 requirements。

## 稿件格式

一个段落标题写 `## [seg-01] 标题`；口播句一行写 `[s001] 这一句的正文。`。可选表达标注写 `> 表达 [s001]：具体、可执行的语气或停顿作用`，不进入 TTS 朗读文本。段落/句子 ID 在同稿唯一；改措辞时保留 ID，拆合句时重分配 ID 并更新下游引用。

句ID在当前协议中也是口播/合成单元，可含几句连贯的话；无需遇到句号就拆行。按说话动作与呼吸组织，字幕和时间继续依据实际返回数据，不新增格式或均分词时间。材料与虚构身份必须可辨，限定放在当前交付中能保证正确理解的位置；完整视频可用持续标识，独立音频须在声音中保持身份，不把后台创作说明当成默认开场。

合成单元不等于字幕显示单元。编译后的 `subtitles` 保留整单元与阅读视图兼容；`subtitleCues` 按真实词时间拆成短字幕并保留正文标点，`subtitleLimitations` 记录降级原因。只有句级时间或词文无法可靠对应时，不均分伪造时间；实际回退须在视听脚本中可见。关键包袱不能用整段提前显示的回退宣称已同步。

`script.md` 允许一个 `#` 文档标题、空行和以上三种内容行；未知非空行必须报告，不能静默丢掉可能要读的正文。引用与来源文字写 `research/` 或 `outline.md`，避免被误读。当前共享解析器导出 `parseScriptMarkdown()`，返回有序的 `{segments, sentences, deliveries}`；`contentDigest()` 覆盖有序段落 ID、句子 ID 与实际正文，`deliveryDigest()` 只覆盖有序表达标注及作用对象。函数签名见 `runtime/shared/content-contract.mjs`。

完整视频先由 story-write 与 story-video 按同一段落/句子 ID 共同构思关键节拍及声画分工，正文审核后再正式配音；单独写稿或无声动画可停在对应阶段。outline保留具体吸引力、观众预期与兑现，direction保留视角、表演和揭示；镜头newInformation字段可以记录处境、认识或感受的作用，不强制新增事实。视频镜头可跨句，单元可含多句，不强制逐句切镜，也不要求新增字段才能采用方法。

## 审核依据与失效

独立审核记录使用 `type: "independent_review"`、`status: "passed" | "needs-revision"`、`basis`、`unresolved` 和问题位置。`basis` 至少含 `scriptSha256`、`rulesSha256`。新建或明确迁移的本期还绑定 `requirementsSha256`；`contentPrinciples` 使用 `{path, sha256}` 数组，按路径排序列共同内容原则、实际适用专项及实际影响判断的参考文件，路径相对 `story-studio/` 根。旧单对象仍可读取，不得只刷新摘要伪称重审。纯制作状态无需绑定 episode；实际影响内容的 episode 决定仍计入依据。

实际使用的骨架、来源和影响理解的视觉设计分别绑定，路径相对本期根。来源数组按路径排序。视觉依据默认对文件原始字节求摘要；`visual/shots.json` 使用 `digest: "visual-content-v1"`，只跟踪单元意义、开始/变化/结束状态、同步意图、来源和场景输入，不跟踪画布尺寸、镜头帧数/位置或音频放置。纯构图/留白调整使视频预演过期，但不自动使正文审核或源配音过期。软件只重算清单中的文件，不自动发现漏列要求或专项；审核者需对照实际输入核查完整性。格式及摘要有效不能证明故事好坏。

外部稿由用户**明确决定冻结**时记录 `type: "user_frozen"`、稿件摘要与实际决定来源。这个分支不是 AI 审核通过；当前任务的操作者必须从可信对话核对该决定，不能因为仓库里出现 `user_frozen` 字符串就自行获得授权。格式示例不含有效凭据；真实验收样例如有独立审核，也只对记录绑定的样例版本有效，不放行其他稿件。

`validateReviewAuthority(review, currentBasis)` 只接受当前摘要逐项匹配、无未解决问题的独立通过记录；用户冻结分支必须由调用方另外明确传入已核实的可信决定。缺项、旧摘要、状态不通过时在请求 TTS 前失败。已缓存音频也不能让旧审核放行新稿。

正文摘要与表达摘要分开。只改有效表达标注且未改正文语义时保留正文审核，重新计算声音缓存和时间；改正文则旧审核失效。`visual/shots.json` 的镜头时长、位置、构图不进入正文审核摘要；声画分工、视觉事实与必要信息若改变，内容审核需要复核相关判断。不能单纯对整个 shots 文件做一个审核摘要。

## 时间与路径

源音频区间统一用秒，零点属于各源文件；`audio/timing.json` 明确音频文件与指纹、稿件与声音输入摘要、实测总长、时间来源与精度。句段时间只有实际确认的粒度；缺逐字信息不以均匀分配填充。

关键配音预演通过 `--ids` 选择完整有效稿件中的单元，只写 `audio/preview-timing.json`（`status: preview`、`selectedIds`），与完整入口隔离。它共享经过摘要校验的音频缓存，但不能作为完整 `audio/timing.json` 传给渲染。总体说话意图与局部表达合并进入声音输入摘要；局部冲突优先，不清除无冲突的总体意图。

配音前 `visual/shots.json` 的时间可为估算并显式标注。最终视频的镜头边界、字幕、音频放置共用一条剪辑时间轴：源入/出点用秒，成片起点与长度按帧率换算为帧；秒转帧统一 `round(seconds × fps)`，相邻镜头共享边界。额外留白占用成片时间，不修改源时间；源音频内已有停顿不得再次添加。无声镜头可以没有音频引用。时间来源或精度不足以支持关键同步时，补对齐或调整画面设计。

最终 `shots.json` 每镜至少有 ID、关联单元/句段、意图、开始/变化/结束状态、场景入口、资源、开始帧和帧数；声音放置另记录源音频 ID、源入/出点、成片起点。阅读视图组合 `script.md`、`timing.json`、`shots.json`，显示“分:秒—说什么—怎么说—画面发生什么”和时间状态。它不得反向修改正文、源时间或镜头。

`output/render-manifest.json` 绑定内容、声音、镜头、场景源码及 `rendererSha256`；运行层或依赖锁文件改变后，旧成片不能沿用为当前程序的效果证据。该指纹不代替实际解码、看画面或听声音。

## 变更次序

共享字段变化先修本文件和格式示例，再通知01/02/03调整各自读写；不建第二套名称。只涉及某包内部的字段留在包内。每个实施包在自己的计划末尾留下实际产物、命令与证据，不用计划中拟建命令代替真实运行结果。
